# Japanese Photo Reader

Local-first Chrome extension for reading Japanese text in webpage images. It captures an image area, runs local OCR, tokenizes the recognized Japanese, looks up dictionary entries, and explains grammar with a local Ollama model.

## Features

- Select an area of a webpage image and recognize Japanese text with Manga-OCR.
- Analyze typed Japanese text from the extension popup.
- View token structure with per-token dictionary entries.
- Inspect a Hanabira-inspired sentence analysis tree with phrase roles and translations.
- Match sentence grammar against local Hanabira Japanese grammar reference data when installed.
- Highlight recognized text in the result panel for dictionary lookup and Google search.
- Ask follow-up grammar questions without rerunning OCR or full grammar analysis.
- Keep all OCR, dictionary lookup, sentence analysis, and grammar analysis local.

## Project Layout

- `backend/`: FastAPI service for OCR, tokenization, JMdict lookup, and Ollama sentence/grammar analysis.
- `extension/`: Manifest V3 Chrome extension UI and content scripts.
- `scripts/start-local.sh`: Starts Ollama when needed, ensures the default model exists, installs backend dependencies, checks CUDA by default, and runs the backend.
- `scripts/stop-local.sh`: Stops the local backend process for the configured host and port.

## Architecture & Design

This project is built around a **100% local, privacy-first architecture** designed to bridge the gap between simple translation and deep language comprehension. It consists of two main pieces: a Chrome Extension (Frontend) and a FastAPI server (Backend).

### 1. Frontend (Chrome Extension)
A Manifest V3 extension that runs seamlessly in the browser. It allows users to drag a selection box over any part of a webpage (like an image, manga, or video frame) or type text directly into a popup. It communicates securely with the local backend to process the data and renders the results—from dictionary lookups to AI-generated grammar analysis—in a clean side panel.

### 2. Local Backend (FastAPI Pipeline)
The backend acts as an orchestration layer, passing the Japanese text through a highly specialized NLP pipeline:
- **Optical Character Recognition (OCR):** Uses `Manga-OCR` (accelerated via CUDA) to accurately extract Japanese characters from the cropped image.
- **Morphological Analysis (Tokenization):** Uses `SudachiPy` to intelligently split the raw Japanese sentence into fundamental linguistic tokens (verbs, particles, nouns, etc.).
- **Dictionary Lookups:** Queries a local `JMdict` SQLite database to provide exact English definitions and readings for every single token in the sentence.
- **Deterministic Grammar Matching:** Compares the tokenized sentence against a rich JSON repository of JLPT (N5-N1) Hanabira grammar rules. These rules are powered by rigid AST logic markers pre-generated by advanced AI, allowing for instant, deterministic detection of complex grammar points without invoking the LLM at runtime.
- **Deep AI Analysis (Ollama):** Forwards the sentence to a locally running Large Language Model (defaulting to specialized reasoning models like `Shisa-32B`). By leveraging Chain-of-Thought reasoning (via a `/think` prompt), the LLM breaks down clause structures, hidden nuances, and verb conjugations to provide a contextual, learner-friendly explanation of *why* the sentence means what it means.

This hybrid approach—combining deterministic dictionary/grammar rules with the contextual reasoning power of a 32B LLM—provides near-instant, tutor-level feedback entirely on your local machine.

## Requirements

- Linux with Python 3.12 recommended.
- Chrome or Chromium-based browser.
- Ollama installed and reachable at `http://127.0.0.1:11434`.
- CUDA-capable GPU for Manga-OCR by default.
- The default grammar model:

```bash
ollama pull hf.co/XpressAI/shisa-v2.1-unphi4-14b-GGUF:Q4_K_M
```

You can override the grammar model with `OLLAMA_TEXT_MODEL`.

## Quick Start

```bash
./scripts/start-local.sh
```

Keep that terminal open while using the extension. The backend runs at `http://127.0.0.1:8000`.

To stop the backend from another terminal:

```bash
./scripts/stop-local.sh
```

By default this leaves Ollama running, because it may have been started outside this project or shared by other tools. To stop Ollama too:

```bash
STOP_OLLAMA=1 ./scripts/stop-local.sh
```

If you need to override settings:

```bash
OLLAMA_TEXT_MODEL=hf.co/XpressAI/shisa-v2.1-unphi4-14b-GGUF:Q4_K_M \
BACKEND_PORT=8000 \
./scripts/start-local.sh
```

Use the same `BACKEND_HOST` and `BACKEND_PORT` values with `scripts/stop-local.sh` if you started the backend on a non-default address.

## Load The Extension

1. Open `chrome://extensions`.
2. Enable Developer mode.
3. Click Load unpacked.
4. Select the `extension/` directory from this project.

Reload the extension after changing files in `extension/`. Refresh already-open webpages so the updated content script is loaded.

## Basic Use

1. Start the local backend with `./scripts/start-local.sh`.
2. Click the extension toolbar button.
3. Click Select area.
4. Drag over Japanese text in a webpage image.
5. The side panel shows recognized text, token structure, dictionary entries for each token, sentence analysis, and grammar analysis.

## Typed Text Analysis

Use the Analyze typed text box in the popup to analyze Japanese text directly. Clicking Analyze text runs tokenization, dictionary lookup, local grammar-reference matching, an Ollama grammar-classifier fallback, fast tokenizer-based sentence analysis, and Ollama grammar prose. AI sentence-tree generation is disabled by default.

The grammar question box is not sent during Analyze text. Ask a grammar question separately after analysis when you want grammar prose for the current sentence.

## Sentence Analysis

The Sentence Analysis section renders a fast tokenizer-based tree by default. The backend still has an optional `explain_sentence_tree` flag for AI-generated phrase grouping, but the extension does not use it in the normal flow.

## Grammar Questions

After analyzing an image or typed text, type a question in the Grammar question box and press Enter. This sends only the current recognized text plus the question to the backend. The existing recognized text, token structure, dictionary results, and automatic grammar analysis stay unchanged; only the Grammar Question Answer section updates.

## Dictionary Lookup

The Structure section includes dictionary matches for each token when available. Particles, auxiliaries, punctuation, and unknown terms may show no dictionary entry.

You can also highlight recognized text in the side panel to run a dictionary lookup for the selection. The result includes a Google search link.

## Optional Hanabira Grammar References

Grammar matching uses local Hanabira Japanese grammar JSON files when they are present in `backend/data/hanabira_grammar/`. The extension enables the Ollama classifier fallback by default for image and typed-text analysis, so local token/rule matches are supplemented with AI-detected grammar candidates before grammar prose is generated. The same downloader also installs Hanabira markdown grammar pages into `backend/data/hanabira_grammar_markdown/`, which lets the extension show a full grammar reference when you click a matched grammar point.

Download or refresh the local grammar references with:

```bash
python3 scripts/download_hanabira_grammar.py
```

The files come from `https://github.com/tristcoil/hanabira.org-japanese-content`. That repository describes the content as Creative Commons and asks users to link back to Hanabira.org when using it. Downloaded files live under ignored `backend/data/` and should not be committed.

Audit grammar matching against one extracted Japanese example sentence from each downloaded markdown file:

```bash
python3 scripts/test_hanabira_markdown_examples.py
```

Run the same audit with the Ollama classifier fallback enabled:

```bash
python3 scripts/test_hanabira_markdown_examples.py --use-ollama-classifier --report tmp/hanabira_markdown_example_report.ollama.json
```

The audit writes a detailed report to `tmp/hanabira_markdown_example_report.json` by default. It is a coverage baseline, not a strict pass/fail gate by default.

## Optional Full JMdict Setup

The app runs without a local JMdict database, but definitions will be limited. To build the local SQLite dictionary:

```bash
mkdir -p backend/data
curl -L http://ftp.edrdg.org/pub/Nihongo/JMdict_e.gz -o backend/data/JMdict_e.gz
gzip -dc backend/data/JMdict_e.gz > backend/data/JMdict_e.xml
python backend/import_jmdict.py backend/data/JMdict_e.xml backend/data/jmdict.sqlite
```

Restart the backend after importing. Files in `backend/data/` are local data and should not be committed.

## Manual Backend Startup

```bash
python -m pip install -r backend/requirements.txt
python -m pip install -r backend/requirements-manga-ocr.txt
cd backend
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Stop that backend with:

```bash
./scripts/stop-local.sh
```

Useful environment variables:

```bash
export OLLAMA_URL=http://127.0.0.1:11434
export OLLAMA_TEXT_MODEL=hf.co/XpressAI/shisa-v2.1-unphi4-14b-GGUF:Q4_K_M
export MANGA_OCR_REQUIRE_CUDA=1
```

Set `MANGA_OCR_REQUIRE_CUDA=0` only if you intentionally want CPU fallback.

## API Checks

Health check:

```bash
curl http://127.0.0.1:8000/health
```

Analyze text:

```bash
curl http://127.0.0.1:8000/analyze-text \
  -H "Content-Type: application/json" \
  -d "{"text":"母に野菜を食べさせられた。","explain_grammar":true}"
```

Answer a follow-up grammar question without rerunning full analysis:

```bash
curl http://127.0.0.1:8000/answer-grammar-question \
  -H "Content-Type: application/json" \
  -d "{"text":"母に野菜を食べさせられた。","grammar_question":"What does 母に mark?"}"
```

Direct Ollama test:

```bash
curl http://127.0.0.1:11434/api/generate \
  -H "Content-Type: application/json" \
  -d "{"model":"hf.co/XpressAI/shisa-v2.1-unphi4-14b-GGUF:Q4_K_M","prompt":"Say hello in one sentence.","stream":false}"
```

## Security Notes

- Keep the backend and Ollama bound to `127.0.0.1`.
- Do not expose this backend directly to a network.
- Do not commit local dictionary databases, benchmark outputs, model files, cache directories, or machine-specific notes.
